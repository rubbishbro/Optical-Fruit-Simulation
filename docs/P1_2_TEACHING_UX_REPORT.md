# Fruitsim P1.2 Teaching UX Report

## Scope

P1.2 adds a separate Teaching Mode on top of the sealed P0/P0.1/P1.1
workflow. Analysis Mode remains the existing Canvas evidence view. Teaching
Mode reads the saved bundle and renders a structured scene; it does not fit a
model or recompute a StageRun in the browser.

## Implemented structure

- `static/ml_p1_teaching.js` contains the `TeachingScene` contract, SVG renderers,
  fixed plot geometry, clipped marks, object badges, and pipeline strip.
- `static/ml_p1.js` owns mode switching, event expansion, linked selection,
  playback, and the existing correctness controller.
- `index.html` exposes Chinese-first labels with English subtitles and an
  explicit Analysis / Teaching switch.
- `static/ml_p1.css` gives Teaching Mode a larger explanation column, readable
  object cards, and a restrained research-style palette without gradients.

## Scene coverage

| Stage | Teaching scene and steps |
| --- | --- |
| Data Inspection | SpectrumSet identity, representative spectrum, matrix framing |
| Preprocessing | SNV sample, mean, centered signal, std, formula, fixed-axis morph; cached comparison support |
| Feature Analysis / PCA | X, Xc, projection, score plot, selected sample linkage, diagnostic-branch warning |
| Feature Analysis / CARS | fixed wavelength axis, iteration retention/removal, normalized importance, internal RMSECV warning |
| Feature Selection | `X_selected = X[:, selected_indices]`, selected wavelength highlighting |
| Modeling / PLSR | SelectedFeatureSet → Latent Scores → PredictionSet → residual and validation view |
| Results | validation metric cards and current ExperimentRun boundary |

The pipeline strip follows raw → SNV → PCA diagnostic branch → CARS →
selection → PLSR → validation. PCA is shown as a diagnostic branch and is not
silently fed into the CARS/PLSR route.

## Data boundary

`scripts/build_teaching_dataset.py` creates the independent deterministic
`SYNTHETIC_TEACHING` run: 128 samples × 61 wavelengths, three categorical
batch groups, smooth target-related structure, nuisance variation, and noise.
Its manifest declares `purpose=visualization_and_teaching` and
`not_experimental_evidence=true`. It is generated by
`scripts/build_web_research_assets.py` and is separate from correctness
fixtures.

## Geometry and rendering QA

The SVG renderer uses one `plotArea` per scene, maps data values through an
explicit scale, clamps points to the plot area, and places all data marks in a
`clipPath` group. CARS keeps wavelength index order and normalizes relative
importance to 0–1. The chart contract does not use magic bar heights.

## Tests and commands

Targeted scene and dataset checks:

```bash
node scripts/test_ml_p1_teaching.js
PYTHONPATH=python python -m unittest python.tests.test_teaching_dataset python.tests.test_p1_teaching_bundle -v
```

Real browser interaction harness:

```bash
PYTHONPATH=python python scripts/test_ml_p1_browser.py
```

The harness uses local HTTP plus headless Chrome and checks mode entry, scene
contract, SNV centered step, raw comparison identity, ExperimentRun playback
source, CARS step zero/order, PCA teaching steps, DAG edges, wavelength
linkage, and pause/resume progress.

## Known limits / P2

- The TeachingScene contract is currently an in-browser contract; an exportable
  Manim timeline is intentionally deferred.
- PCA loadings and the Unity object are linked by sample/wavelength identity in
  the web UI; a future Unity overlay can consume the same stable IDs.
- Teaching Mode uses the existing saved CARS states and does not claim nested-CV
  unbiased performance.
